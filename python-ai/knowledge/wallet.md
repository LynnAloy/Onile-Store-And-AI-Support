# 演示钱包与支付验证

健康钱包属于本项目的演示账本，不是第三方支付平台或真实银行账户。使用钱包前先设置六位数字支付密码。

支付密码只填写在独立的支付确认或钱包授权设置表单中，不应发送给AI模型。Java服务端校验当前用户与支付密码，验证失败不能扣款。支付密码连续验证失败五次后暂时锁定十五分钟。

启用独立付款时，验证成功仅签发绑定当前用户会话、订单版本、金额和币种的短期授权，最长六十秒，不直接扣款。付款需要用户另行点击“确认付款”；授权只保存在页面内存中，离页、撤回或退出时清理。付款结果不确定时只查询原订单，不自动更换请求键或再次扣款。未启用此流程的环境维持原购药页面，具体以页面环境提示为准。

充值卡只能使用一次。积分兑换数量必须是正数且不能超过当前积分。所有余额、积分与交易流水以Java服务端和数据库为准，前端展示不代表支付已经成功。

尚未接入真实第三方支付。真实支付回调验签、退款等能力属于后续开发范围。


钱包“允许 AI 智能下单”默认关闭。开启后明确购买消息可自动下单并扣演示余额：默认单笔 50 元、每日 200 元，日界为 PST 固定 UTC−08:00，夏季也不切换为 PDT。开启、重新开启或提高额度需支付密码验证；关闭或降低额度无需密码。授权仅对当前登录有效，关闭、重新登录、重新启用都不能清零当日已扣额度。一次购买轮次只扣一次，失败和未成交订单不占额度；人工付款不计入 AI 自动额度。收货信息由 Java 从个人资料读取，不给模型。自动付款资格与健康档案上下文开关相互独立。


P1风险门禁补充：开启钱包自动下单不等于通过健康风险复核。自动交易还需要用户授权健康资料、年龄18至64岁、完整且明确的无病史/无已知过敏/无当前用药自述，以及其他健康信息明确为“无其他健康风险”；应按真实情况填写，不能为了启用功能虚填。存在风险、信息不足或商品证据缺失/失效时，只生成清单并转人工核对，不自动扣款。这是演示自动化门禁，不是用药安全证明或药师审核。

管理员在药品管理的“审核证据”维护分类、成分、适用范围原文、来源与单次自动购买件数上限。类别检索仅返回有有效审核依据的匹配，输出证据来源和版本；点名查询库存不等于确认该商品属于医疗类别。模型推测不能代替审核事实。

扣款结果未知后，即使查询失败或登录过期，也不能声称未扣款；请恢复登录后查询原轮次或付款订单，不重复发送购买消息。
