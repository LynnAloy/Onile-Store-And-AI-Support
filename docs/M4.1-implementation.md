# M4.1 实现与验证：只读工具调用

实现日期：2026-10-27。M4.1 为真实模型选择的只读 Tool Calling，
包括实时商品搜索、商品详情和本人订单摘要。Java 继续拥有业务数据，
Python 负责工具编排，Vue 展示经服务端校验的查询卡片。

## 已实现能力

| 模型工具 | 严格参数 | Java 内部 GET |
|---|---|---|
| search_medicines | name: 1–100 字符；limit: 整数 1–10，默认 5 | /internal/ai/v1/medicines?name=...&limit=... |
| get_medicine | medicineId: 正整数 | /internal/ai/v1/medicines/{id} |
| get_my_order | orderId: 1–64 位字母、数字、下划线或短横线 | /internal/ai/v1/orders/{orderId} |

Java 查询目录默认 10 条、最多 20 条，并按 id 升序；Python 工具上限更严格。
商品为空、库存为零、商品或本人订单不存在均有明确结果。
订单读取沿用 Java 的当前用户归属检查，跨用户访问返回 NOT_FOUND。

工具只允许固定服务地址和固定路径，用户身份与双重凭证在 Python 服务端注入；
模型不能指定 URL、userId、价格、权限或支付状态。
参数拒绝额外字段、字符串冒充整数、布尔值冒充整数和路径注入。
Java 响应经白名单再次裁剪，订单摘要不携带收货人、电话、地址或支付凭证。
金额以 Decimal 校验后转换为两位小数字符串，工具链不做浮点金额计算。

## 模型与协议

使用 Ollama 原生 /api/chat tools 和 message.tool_calls。
模型的普通文本、Markdown JSON 或函数名称不会触发业务请求。
原生结构化调用也必须通过注册表和参数校验，模型不能扩展工具集合。
工具响应以 role=tool 返回模型，后续模型请求仍可选择允许的只读工具，
最终回答通过原有 SSE delta 流返回。

本机 Qwen2.5:latest 是自定义模板：最初返回模拟调用文本，补充提示后仍出现流式空参数。
本次基于同一份本地权重创建独立别名 deepseekdoc-qwen2.5-tools:latest，
采用 [Ollama 官方 Qwen2.5 工具模板](https://ollama.com/library/qwen2.5:latest/blobs/247824859003)。
原模型保留，无需下载新权重。协议依据：
[Ollama Tool Calling](https://docs.ollama.com/capabilities/tool-calling)。

可复现命令（项目根目录）：

~~~powershell
python scripts/prepare_tool_model.py --use-local-config
~~~

脚本复用已有权重；已存在的项目别名若模板不一致则拒绝覆盖。
模板文件为 scripts/ollama/qwen2.5-tools.gotmpl，
来源模型摘要、别名摘要和模板 SHA256 记录在 .local-run/tool-model.json。
--use-local-config 只更新 .env.local 的 OLLAMA_MODEL，不打印其他配置。
自备模型必须真实支持 tools；HTTP 400 拒绝工具时返回 MODEL_TOOLS_UNAVAILABLE，
不会悄悄改成关键词路由。

## 执行边界

- 每轮最多 4 次模型生成、3 轮实际工具执行、总共 6 次工具调用，顺序执行。
- 整批参数先验证，未通过时任何调用都不执行；最多一次固定协议纠正，
  不回显无效参数，再次失败返回 INVALID_TOOL_CALL。
- 只读 GET 每次超时 5 秒，最多 2 次尝试，仅网络失败或特定临时状态重试；
  身份失效和 NOT_FOUND 不重试。
- 原始响应最多 32768 字节，裁剪后的结果最多 6000 字符；
  工具消息累计受上下文预算限制，超出明确报错，不截断 JSON 或健康字段。
- 生成总超时、输出上限、取消、资料授权变化和知识版本变化沿用原有控制；
  每次业务查询前后再次验证绑定。
- 服务端生成 callId，同时作为 Java X-Request-ID，模型不能指定。
- 轨迹只保留工具名、参数摘要、结果白名单、状态与耗时：
  搜索关键词只记录长度，订单参数只记录末尾六位；完整订单标识只存在于本人的查询结果。
- 工具结果是不可信数据，系统提示禁止执行其中指令；工具集合本身没有写操作。
  Vue 通过插值显示文字，不渲染任意 HTML 或模型提供的操作链接。

上述限制不构成模型事实正确性的形式化证明；商品命中不等于临床适用。
现有资料不足以支持按症状推荐药物或剂量，页面与提示均明确该边界。

## SSE、持久化与历史

新增 tool_started 和 tool_result：

~~~json
{
  "callId": "服务端生成UUID",
  "tool": "search_medicines",
  "argumentsSummary": {"keywordLength": 4, "limit": 5},
  "status": "completed",
  "durationMs": 30,
  "result": {
    "ok": true,
    "products": [
      {"id": 1, "name": "商品名称", "price": "0.37", "stock": 0, "currency": "CNY"}
    ],
    "queriedAt": "UTC ISO时间",
    "snapshot": true
  }
}
~~~

tool_started 的 status 为 running，不包含 result/durationMs。
业务查询失败产生 status=failed 的 tool_result，含受控 code/message，模型可以说明失败；
身份、协议、上限或上下文失效导致 SSE error，本轮不记为完成。

SQLite 为 turns 增量增加 tool_events JSON 列，已有对话不清空。
started/result 在发送前保存；取消时未完成的轨迹可在历史中显示“未完成”。
历史读取和已完成请求回放返回原快照，绝不自动重放业务查询。
历史工具回答中的价格、库存、订单状态不再进入模型上下文，
只保留商品/订单标识用于解析后续指代，每个新查询需要重新调用工具。

同时修复回放时未携带非零资料/知识版本绑定导致误报上下文变化的问题，
增加非零版本回放测试。授权/版本确实变化时仍拒绝回放。
