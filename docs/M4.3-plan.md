# 下一阶段计划：M4.3 验收与可复现演示

状态：已完成（2026-10-27）。验收见 M4.3-validation.md，审查见 M4.3-review.md，复现见 M4.3-operations.md。
前置：M4.1/M4.2、购买数量修复与聊天UI调整已完成。
目标：形成可重复运行的登录态浏览器闭环、隔离演示数据和可核验的交付记录，
再进入 M5 支付开发。本计划不授权修改真实药品审核结论。

## 执行顺序

### M4.3-A：隔离演示与测试数据（P0）

- 建立与当前数据分离的演示/端到端测试配置，数据库、会话库、知识索引和凭证分开。
- 准备明确标注为虚构的演示商品，覆盖模拟可售、UNKNOWN/PENDING、RX、缺货和调价。
  模拟审核元数据只用于演示库；不把当前枇杷露、布洛芬直接改为已审核。
- 提供初始化、重置和清理命令，重置前校验目标环境；
  只清理本次成功创建的账号/记录，保留当前用户和业务数据。
- 演示环境显示明确标识，避免与真实目录混用。

验收：首次启动与重复初始化可复现；误指向当前业务库时拒绝执行破坏性重置；
异常中断后能定向识别测试数据，不输出凭证、收货资料或健康档案。

### M4.3-B：登录态浏览器端到端闭环（P0）

此前已有接口/协议测试和未登录窄屏观察，本阶段补齐实际控件操作和登录态视觉验收。

主流程：
登录测试账号 -> 输入购买需求 -> 真实目录工具查询 -> 数量清单预填 ->
勾选/取消/改数量 -> 打开核对抽屉 -> 独立授权 -> 草稿生成 ->
进入我的草稿 -> 独立填写合成收货资料 -> 确认，最终仍未付款。

必须包含：
1. “帮我下单5件枇杷露，3件布洛芬”语义等价用例，分别保持5和3，不交换、不默认为1。
2. 未审核商品可勾选、取消、改数量，但不能授权准备；阻断原因可见。
3. 合法演示商品可完成草稿链路；双击、重复模型调用、刷新不能创建重复草稿。
4. 没有数量时要求补充；多规格匹配时要求选定具体商品。
5. 真实SSE生成、停止、重连/刷新、历史加载与请求回放。
6. 授权撤回、授权请求未返回时撤回、账号切换和退出登录不泄露旧状态。
7. 跨用户草稿/订单访问被拒绝，收货资料不进入模型请求。
8. 长消息、多个工具卡片、10项清单、抽屉滚动、键盘发送、上翻阅读和回到最新消息。

布局尺寸：桌面1366×768、窄屏450×668、手机390×844；
检查页面级横向溢出、输入区可见、消息区独立滚动及抽屉操作可达。
截图仅使用合成数据，不读取或公开真实用户聊天和档案。

验收：主流程可由一次测试命令重复执行；每个失败定位到具体页面/步骤；
保留截图和报告；确认后余额、库存、成交订单数不变。

### M4.3-C：异常与业务回归收口（P0）

- 回归 M1认证钱包、M2会话、M3授权/RAG、M4工具与草稿。
- 草稿过期、缺货、调价、审核版本变更、支付权限越界均在页面明确反馈。
- 真实模型失败与模拟协议异常分开报告：超时、无工具能力、错误参数、
  结果不确定、取消与重复请求。
- 验证不确定写结果只引导恢复查询，不自动换授权或重复创建。
- 完成一次代码审查，修复阻断问题后复验。

验收：既有关键回归通过；无越权、重复草稿、意外扣款/扣库存、
数量错配或输入区不可达的未修复阻断项。不能仅以构建成功代替业务验收。

### M4.3-D：固定评测与交付材料（P1）

- 固定一组版本化用例，覆盖商品查询、数量提取、歧义、审核拦截、授权和草稿。
- 分别记录商品匹配、数量准确性、原生工具调用、草稿业务成功、失败恢复与耗时。
  “被正确拦截”按相应用例成功统计，不混入合法草稿成功率。
- 至少多次重复运行模型用例，保留原始统计与模型/模板/知识版本；
  不用单次全过或小样本命中率代表生产可靠性。
- 更新架构图、状态图、Java/Python契约、迁移/启动/恢复说明。
- 准备毕业设计演示脚本：正常闭环、未审核阻断、调价阻断、
  用户隔离、授权撤回各一段。
- 简历材料只描述已实现的RAG、权限边界、工具编排、幂等和未付款草稿，
  不宣称医学审核、自动成交或真实第三方支付已经完成。

交付：M4.3-validation.md、端到端测试报告、合成数据截图、固定评测集与统计、
可复现演示命令、审查记录。

## 完成门槛

- 隔离演示环境可启动、可复现、可定向清理。
- 登录态浏览器主流程与关键异常通过，真实业务数据保留。
- 接口/协议检查与构建通过，证据对应实际版本。
- 审查中未修复阻断问题清零。
- 明确 CONFIRMED 仍未付款；医学资料及处方审核仍在当前范围之外。

## 随后的 M5 拆分方向

M5.1：先冻结 Java 订单/支付状态机和接口契约，再接入演示钱包支付闭环：
待支付订单、独立支付密码验证、短期一次性支付授权、资格/价格/库存再校验、
余额扣减/库存扣减/订单与流水的同事务提交、并发幂等及超时关闭。
登录凭证、代理凭证和支付授权不混用，AI不持有支付权限。

M5.2：在演示钱包闭环稳定后，再接第三方支付沙箱、回调验签、
重复/乱序回调及对账。实际药品开放销售前，还需真实资料与可信审核维护流程；
演示商品不能替代这一要求。
