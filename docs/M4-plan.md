# M4 任务计划：工具调用与待确认订单

状态：M4.1、M4.2、M4.3 已完成，M4.3验收与审查见 M4.3-validation.md、M4.3-review.md。
前置：M3 框架、平台规则库及本机联调已完成。
目标：用户明确指定商品或提出购买需求后，AI 可查询真实目录、展示可购买候选，
在用户授权准备订单后生成可审阅的订单草稿；确认、支付与最终扣款由 Java 用户接口执行。

## 当前约束

- 目录已增加销售分类、审核状态、来源与版本；原训练商品仍未审核，医学说明书与可信审核维护流程未上线。
- 现有 RAG 只有平台规则，不能支持按症状给出药品适用性或剂量结论。
- 健康档案上下文授权与订单准备授权分别管理，不能相互替代。
- 旧 POST /api/orders 会直接验证钱包密码并成交；不得用作智能体下单工具。
- 本阶段不接入真实第三方支付；钱包流程继续明确标为演示。
- 所有任务以增量迁移实施，保留已有用户、订单、钱包和授权数据。

## M4.1：只读工具调用闭环（优先实施）

Python：
1. 工具注册表与严格参数模型（拒绝额外字段），模型适配层支持 Ollama 原生 tool_calls。
2. 首批工具 search_medicines、get_medicine、get_my_order；
   知识检索仍由现有受控 RAG 执行，避免重复检索与模型自行更改来源审核约束。
3. 服务端注入代理身份、服务密钥和请求追踪 ID，模型不得提供或看到凭证。
4. 每轮限制工具轮数、总调用次数、参数大小、超时和返回体大小；
   只读请求可有限重试，取消、授权撤回、知识版本变化继续中止整个编排。
5. 工具结果按白名单裁剪，作为不可信数据输入，不执行其中的指令。
6. 记录结构化工具轨迹：工具名、参数摘要、业务错误码、耗时；
   不记录密码、凭证、完整健康档案或收货信息。
7. 无工具能力、伪造工具名、无效参数或失败时给出明确错误，不声称完成操作。

Java：
- 复用现有 AGENT_READ 内部商品、订单摘要接口。
- 校验并补齐商品查询数量上限、稳定排序和订单归属。
- 订单摘要不包含收货地址和联系方式。

Vue：
- SSE 新增 tool_started、tool_result，展示查询状态与真实商品卡片；
  商品展示价格库存为查询时快照，订单准备时重新计算。
- 工具事件不直接渲染任意 HTML、URL 或模型生成的操作权限。
- 刷新历史可恢复工具执行结果摘要，不自动重放工具调用。

验收：
- “查找名称含某关键词的商品”实际触发目录查询，商品 ID/价格/库存与 Java 一致。
- 查询不存在商品、库存为零、无权订单、Java 超时均有可理解结果。
- 按症状询药时不把商品关键词命中当作医学推荐，不编造药效或剂量。
- 模型越权、参数注入、循环调用、取消和中途撤回有自动化检查。
- 使用本机 Ollama 实测工具调用能力；不支持时明确报告能力缺失，不以关键词路由冒充 tool calling。

## M4.2：商品资格数据与订单草稿

Java：
1. 新增商品销售资格字段：处方分类 UNKNOWN/OTC/RX、审核状态、关联资料引用。
   既有商品默认 UNKNOWN、未审核，不批量假定为 OTC。
2. 实现资格检查：UNKNOWN、未审核、处方条件未满足时禁止生成可成交草稿；
   说明书、审核和商品映射独立于模型判断。
3. 新增 order_drafts 和明细表，建议状态：
   PREPARED -> CONFIRMED / CANCELLED / EXPIRED。
   CONFIRMED 仅表示用户确认，不代表已支付。
4. 草稿创建、取消、过期、归属、版本及幂等由 Java 管理。
   草稿不扣款、不减库存；成交时在事务内重新校验价格和库存。
5. 同一幂等键同内容返回同一草稿，不同内容返回 409。
6. 用户通过独立入口开启短期订单准备授权，签发 AGENT_ORDER_PREPARE；
   默认不开启，绑定父会话并支持撤销，不能支付。

拟议接口（实施前更新 OpenAPI 并与现有错误体保持一致）：
- POST /api/auth/order-agent-token：USER 发起短期订单准备授权。
- POST /internal/ai/v1/order-drafts：AGENT_ORDER_PREPARE + 服务密钥。
  Header: Idempotency-Key；body: items[{medicineId, quantity}]。
  用户身份、价格、金额、订单状态全部由 Java 确定。
- GET /api/order-drafts/{id}：USER 查看本人完整草稿。
- POST /api/order-drafts/{id}/cancel：USER 取消本人草稿。
- POST /api/order-drafts/{id}/confirm：USER 确认当前草稿版本；
  不接受模型提供的“已确认”，不产生扣款。

Python：
- 新增 prepare_order_draft 工具，只有明确的购买意图及有效订单准备授权时可调用。
- 工具输出只含草稿标识、商品、金额、有效期及状态，不含收货信息。
- 授权撤回后禁止新写操作；已完成草稿保留 Java 可查询记录，避免取消导致写入结果丢失。

Vue：
- 商品候选 -> 准备授权 -> 草稿卡片 -> 用户详情核对。
- 用户在独立业务页面填写或选择收货信息，AI 上下文不读取这些字段。
- 只有服务端确认状态可显示确认成功；过期、调价、缺货有重新核对入口。

验收：
- 模型无法伪造价格、用户身份、支付状态或创建他人草稿。
- 重复调用不创建重复草稿；取消/断线后可按幂等键恢复结果。
- 未审核/未知分类商品被拦截，既有商品数据保留。
- 本机合成演示商品可走草稿流程，但明确为测试夹具，测试后定向清理。

## M4.3：集成回归与交付材料

下一阶段的执行顺序、登录态浏览器验收和隔离演示要求见 M4.3-plan.md。

1. Java 业务测试：授权、商品资格、幂等、草稿状态机、所有权、并发确认。
2. Python 测试：工具协议、边界、注入、异常、上下文变更与轨迹持久化。
3. Vue 测试和构建：工具事件、商品卡片、确认界面、失效授权。
4. 真实 MySQL + Java + FastAPI + Ollama + Vue 代理联调；
   同时回归 M1 钱包、M2 会话、M3 授权撤回与 RAG。
5. 更新机器可读契约、架构/时序图、迁移/运行说明和固定评估用例。
6. 报告真实工具调用成功率、错误恢复情况和耗时；区分“工具执行成功”与“回答正确”。

交付门槛：各层语法/构建通过，关键业务测试通过，合成账号端到端联调通过，
用户数据保留，不把未实现的医学推荐或支付能力写入简历。

## 后续 M5

具体拆分、接口草案及验收门槛见 [M5-plan.md](M5-plan.md)，首先实施M5.1-A契约冻结。
