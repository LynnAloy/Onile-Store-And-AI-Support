# P1 修复验收

对应全链路审查 R1/R2/R3，本次没有扩展到全部P2任务。

## R1：金融结果未知不能被查询错误降级

fulfillAutoProposal保留原写操作的UNKNOWN。后续401、503、网络或解析错误不再变成REJECTED，保留原turnId供恢复登录后核对。仅服务端明确PAID/REJECTED时采纳终态。没有服务端结果标识的金融写入5xx也按UNKNOWN处理；非终态或异常成功响应只触发原轮次查询。实际写请求发出前按用户/轮次保存不含凭据的sessionStorage核对标识；仅对确实尝试过写入的READY恢复待核实，不把风险转人工的只读清单误报为可能扣款。恢复不自动重发扣款，明确终态后清理标识。

前端回归覆盖原写UNKNOWN后读取401/503，确保异常仍为UNKNOWN。未重做完整READY到EXPIRED状态机，该项仍属P2。

## R2：授权健康资料参与图中的保守风险复核

agent将prepare_context得到的授权上下文交给库存图。图的风险复核读取userReportedHealth与omittedHealthFields；纯任务解析/商品筛选模型不获得整个健康档案。输出healthProfileUsed、decision、reasons和notice，不输出“医学安全”结论。

Java独立执行PurchaseRiskService，不信任前端或模型的安全标签。未授权、年龄缺失或不在18-64范围、病史/过敏史/在用药非明确无风险自述、其他病史或健康记录、其他健康风险未明确时，不自动扣款。暂时仅接受明确的无风险自述，语义不清或未完整填写时转人工，不用LLM猜测。商品还需有效证据及单次自动件数限制。前端改为MANUAL，直接绕过前端也被Java阻断。

这是演示自动化门禁，不是诊断、临床禁忌知识库或医生/药师审核。人工流程保留用户核对与支付密码验证，未建立药师履职或处方审核。

## R3：真实ID不能代替类别依据

新增medicine_evidence表，管理员入口“药品管理→审核证据”。记录审核分类、成分、适用范围原文、来源、审核人、证据版本及绑定商品审核版本，以及单次自动购买件数上限。保存前检查管理员身份与版本，并记入medicine_admin_audit。现有商品不自动补证据、不按模型知识推定审核通过。

Java目录只提供与当前审核版本匹配的证据。类别筛选必须匹配已审核类别并回填来源、版本；按具体名称查询库存不等于判定其属于问题中的医疗类别。证据不足时明确说明无法确认，不把它说成全库没有相关药品。

证据修改与商品结算通过商品行锁及证据事务锁串行化，结算重新读取当前证据。商品审核版本变化后旧证据失效，管理员可看到STALE并重新核实。

## 迁移及配置

scripts/p1_migrate.py --environment normal|demo：要求已验证的M6部署，目标服务停止，先创建受保护备份再新增表；不改已有药品或用户健康资料。启动脚本校验证据表结构与迁移目标，设置MEDICINE_EVIDENCE_ENABLED。未启用门禁时自动扣款失败关闭，不退回旧的无健康复核结算。

API新增GET/PUT /api/admin/medicines/{id}/evidence。GET无证据返回version=0与当前qualificationVersion；失效记录返回STALE及旧证据version，允许基于当前商品版本重新审核。返回的图结果扩展riskAssessment、matchedEvidence、evidenceRequired。没有个人健康资料输入、RAG或商业证据时，不假装完成医学风险核查。
