# M4.2：商品资格、独立订单准备授权与未付款草稿

实现日期：2026-10-27。Java 管理资格、授权、草稿和确认；
Python 仅在本轮明确的商品/数量授权下调用 prepare_order_draft；
Vue 提供商品选择、授权、恢复与独立确认页面。

本阶段不创建成交订单，不扣款、不扣库存，不接入第三方支付。
CONFIRMED 仅表示用户已核对资料，不代表 PAID 或完成购买。

## 完整交互

1. 用户通过对话查询真实商品。搜索结果本身不是用药推荐。
2. 用户在卡片选择数量，可选择最多10种商品；点击独立的“授权AI准备…草稿（不付款）”。
3. Vue 使用 USER 凭证申请短期 AGENT_ORDER_PREPARE，绑定确切商品、数量和父会话；
   这与健康档案上下文授权相互独立，默认不存在。
4. Vue 向 FastAPI 发出明确 purchaseIntent，并以独立请求头传递订单准备凭证。
   普通对话仍使用 AGENT_READ，两种凭证都不进入模型输入。
5. 本轮才提供 prepare_order_draft。模型只能返回授权中的商品和数量。
6. Java 验证资格、当前价格和库存，生成有效期15分钟的 PREPARED 快照；
   相同授权的请求键始终对应同一草稿。
7. 用户进入 /drafts 核对当前数据，独立填写收货人、手机号与地址。
   Java 再次校验资格、价格、库存和版本后确认，仍然不付款。
8. 网络中断或停止生成后，可通过“我的草稿”或请求键查询恢复已保存结果。

~~~mermaid
sequenceDiagram
    participant U as 用户/Vue
    participant J as Java业务
    participant P as Python智能体
    participant M as Ollama
    U->>J: USER + 明确商品数量，申请订单准备授权
    J-->>U: 独立短期凭证、固定请求键
    U->>P: AGENT_READ + purchaseIntent + 独立订单准备凭证
    P->>J: 验证用户/商品/数量/有效期绑定
    P->>M: 本轮可用的草稿工具与授权商品（不含凭证）
    M-->>P: 原生 prepare_order_draft 调用
    P->>J: 指定商品数量 + 服务端请求键
    J-->>P: 未付款草稿白名单
    P-->>U: 草稿卡片
    U->>J: USER + 版本 + 独立收货资料，确认
    J-->>U: CONFIRMED，未付款、不占库存
~~~

## 销售资格门禁

medicines 新增：

- sale_classification：UNKNOWN / OTC / RX，存量默认 UNKNOWN。
- review_status：PENDING / APPROVED / WITHDRAWN，存量默认 PENDING。
- reference_source：审核依据引用，http(s):// 或 local:// URI。
- reviewed_by：审核维护者标识。
- qualification_version：正整数审核版本，默认0表示未完成审核。

只有 OTC + APPROVED + 完整依据/维护者 + 有效版本与价格才能准备草稿。
所有 RX 当前被拦截，因为尚未实现独立处方核验。
资格未知、未审核、已撤回、依据不全、价格无效或库存不足均不能通过。
同一 SalePolicy 也用于原有 POST /api/orders，防止通过旧购物车绕过资格检查。

没有把现有商品批量标为 OTC，没有编造医学说明书或批准记录。
这些字段是可信维护者录入后的服务端门禁，尚不是完整药师审核工作台，
也不会自动判断引用内容的医学正确性。

后续真实资料录入：维护者先核实实际说明书/来源与分类，在数据库维护窗口
原子更新资格字段、审核人、来源与 qualification_version = qualification_version + 1。
当前没有向普通 USER 开放资格修改 API。测试中的 local://synthetic-tests 仅为隔离合成夹具，
用后定向删除，不属于可用于医学建议的正式资料。

## Java 接口契约

所有成功响应为 Cache-Control:no-store。接口不以模型提供的 userId 授权。

| 接口 | 凭证 | 作用 |
|---|---|---|
| POST /api/auth/order-agent-token | USER | items[{medicineId,quantity}]，签发绑定商品的授权 |
| DELETE /api/auth/order-agent-token | USER | 撤销当前账号所有订单准备授权 |
| GET /internal/ai/v1/order-preparation | AGENT_ORDER_PREPARE + 服务密钥 | 用户、商品、请求键、到期时间绑定 |
| POST /internal/ai/v1/order-drafts | 同上 | 按绑定商品与 Idempotency-Key 准备/恢复草稿 |
| GET /api/order-drafts?requestKey=可选 | USER | 本人最近50条草稿或按请求键恢复 |
| GET /api/order-drafts/{id} | USER | 本人草稿、当前数据与确认阻断原因 |
| POST /api/order-drafts/{id}/confirm | USER | 版本 + 收货资料，确认但不付款 |
| POST /api/order-drafts/{id}/cancel | USER | 版本，取消 PREPARED 草稿 |

订单准备凭证最多300秒，且不超过父 USER 会话有效期；不能访问普通 USER API，
不能确认、支付，也不能替代 AGENT_READ 调用通用查询。
用户登出、重新登录或父会话失效后，旧订单准备凭证失效。
每账号同时最多10个有效订单准备授权。

请求示例：

~~~json
{"items":[{"medicineId":1,"quantity":2}]}
~~~

最多10行，商品ID不能重复，quantity 为1–99整数。
JSON 浮点数或字符串不能隐式转换为整数。
商品顺序规范化后比较，不接受模型提供价格、用户ID、余额或状态。
请求键由 Java 签发；Python 从绑定接口获取并注入，模型不能选择或修改。

确认示例（仅发送到 Java USER 接口）：

~~~json
{"version":1,"recipientName":"收货人","recipientPhone":"13800138000","recipientAddress":"收货地址"}
~~~

完整机器契约见 java-python-contract.openapi.json 和 fastapi-contract.openapi.json。

## 状态、并发和数据一致性

~~~mermaid
stateDiagram-v2
    [*] --> PREPARED
    PREPARED --> CONFIRMED: USER版本及资料确认
    PREPARED --> CANCELLED: USER取消
    PREPARED --> EXPIRED: 15分钟到期
~~~

EXPIRED 在服务端读取/操作时根据到期时间计算，当前没有定时批量更新状态任务。
CONFIRMED 为本阶段终态，后续支付阶段仍需重新验证有效期、价格、资格和库存。
没有库存预留，因此多个合法草稿可以引用相同库存，确认也不保证将来支付时有货。

准备、撤销、确认、取消和父会话切换使用同一账号行锁串行化；
商品按ID顺序加锁。写入前再次验证凭证，覆盖等待商品锁期间授权过期。
撤销先完成时旧凭证不能写入；草稿先提交时保留该结果，撤销不能追溯删除已经完成的操作。

订单草稿与明细在同一事务内保存，user/request_key 和 grant_hash 具有唯一约束。
重复准备返回同一草稿；不同商品、数量或请求键返回409。
确认使用乐观版本，同一确认内容重复请求返回已确认结果；
不同内容不能覆盖已确认资料。确认与取消并发时只有一个成功。
价格变化返回 PRICE_CHANGED，库存不足返回 OUT_OF_STOCK，
审核版本变化返回 QUALIFICATION_CHANGED；不悄悄接受新价格或新版本。

草稿表保留授权哈希、请求键和内容哈希，即使授权撤销/会话删除，草稿仍可由本人恢复。
授权表以外键随 auth_sessions 删除；不会保存明文凭证。
收货字段只存 Java 业务草稿表，只在本人 USER 视图中返回。
内部工具视图和 Python 二次白名单均排除姓名、电话和地址。

## Python 工具边界与失败恢复

消息正文新增 purchaseIntent，必须与 X-Order-Agent-Token 同时出现；
主 Authorization 仍是 AGENT_READ。Java 绑定的用户必须与当前对话用户相同，
商品和数量也必须一致。没有结构化购买意图时不提供写工具。

每次调用前后、生成期间继续检查订单授权与原有资料/知识版本绑定。
每轮仍最多4次模型生成、3轮工具执行、6次调用。
prepare_order_draft 在单轮内最多真正发送一次 POST，重复模型调用复用该结果。
POST 不自动重试；网络超时、服务器异常、超大/异常响应或“已付款”假快照
统一返回 DRAFT_OUTCOME_UNKNOWN，要求查看本人草稿。
不能把未知结果当作明确未创建，更不能因中断自动生成新授权。

requestId 额外绑定订单准备 requestKey，换授权不能回放同一请求。
Python SQLite 仅保留对话、工具结果快照和非凭证请求键，不保存订单准备凭证或收货资料。
取消/撤回时已经写入 Java 的草稿可能无法通过原 SSE 返回，USER 草稿列表是恢复入口。
前端撤销会使尚未完成的授权请求失效，防止其稍后继续自动发起草稿准备。
