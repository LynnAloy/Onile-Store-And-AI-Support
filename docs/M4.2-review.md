| 收货资料可能经草稿回放或工具响应泄露 | Java 内部视图白名单 + Python 草稿白名单；换用户清空页面字段 | 确认后内部恢复无收货信息；模型请求无凭证或收货信息 |

## 核验的关键不变量

1. 普通对话不提供草稿工具；健康资料授权不能授予订单准备权限。
2. 订单准备凭证绑定当前用户、商品数量、父会话、期限和固定请求键。
3. 模型不能提交用户ID、价格、余额、已确认/已支付状态；不具备确认和支付工具。
4. 撤销与准备以账号锁排序：撤销先完成时旧授权不能新增草稿；
   撤销前已提交的草稿保留，用户可通过本人列表/请求键恢复。
5. 同一授权、相同请求内容只对应一个草稿；并发准备亦不重复。
6. USER 确认前重新核验价格、库存、审核版本；确认与取消并发只有一个成功。
7. 准备、取消和确认均不修改余额、库存或成交订单表；CONFIRMED 始终未付款。
8. 收货资料只经 Java USER 接口传输，不发送至模型、公共知识库或 Python 会话数据库。
9. 写响应不确定时不会盲目重试或自动换新授权，历史/SSE中断不否认已提交草稿。
10. 增量迁移保留现有用户和商品，旧商品默认未知/待审核，不伪造审核资料。

本次发现的问题已修复，未发现尚未修复的发布阻断项。

现有商品会因未知/待审核而被拦截，需要真实依据和审核记录才能开放。
CONFIRMED 草稿没有生成可支付成交订单；M5 必须独立完成支付验证与成交事务，
不得因已有“已确认”状态而省略价格、资格、库存及支付授权检查。
