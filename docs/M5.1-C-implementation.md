# M5.1-C：独立付款与恢复交互

后续状态：M5.1-D综合故障验收已完成，见[M5.1-D-validation.md](M5.1-D-validation.md)。以下保留C阶段的交付范围与已知待验项目。

日期：2026-10-28。状态：已完成；完整故障验收M5.1-D仍待实施。
Java负责资金、库存、资格和事务，Python继续仅提供AI/RAG与原有授权工具；本次没有新增AI支付能力。

## 用户流程

1. 在“我的草稿”核对商品与收货信息，点击“确认资料（不付款）”。
2. CONFIRMED草稿点击“进入独立付款（不扣款）”，Java返回唯一的待支付订单。
3. 独立付款页展示商品数量、快照金额、演示钱包标识、15分钟付款期限与“不预占库存”。
4. 用户打开验证弹层，输入支付密码并点击“验证（不扣款）”。验证成功仅签发短期授权。
5. 弹层关闭后，用户另行点击“确认付款 ¥金额”，才提交付款。成功显示Java支付回执。

新路由为/payment/:orderId与/payments；侧栏、个人中心和草稿页均提供入口。
启用新模式时，旧购药页展示草稿流程指引，旧orderStore也拒绝旧直接提交，避免提示输入密码后才被409拦截。
历史订单以LEGACY_UNVERIFIED展示，不提供新付款按钮。已付款不能关闭；待支付订单关闭须二次明确确认。

## 身份、凭证与恢复

paymentClient.mjs直接使用发起时捕获的USER身份，不经过会自动替换当前token的Axios请求拦截器。
每次更新界面均检查用户、父会话、订单上下文和请求代次。旧响应不得写入新账号或新订单页面。
通用Axios拦截器也增加原请求token检查，旧会话的401不能清除后来登录的新账号。

密码不trim，立即从输入框清空，只用于独立验证请求；不写URL、存储、聊天历史、工具参数或日志。
授权原文仅保存在paymentFlow闭包内，视图只收到是否已验证与到期秒数。
离页、退出、切号、主动撤回和过期清理授权；迟到响应只按原身份、订单和authorizationId定向撤销。
撤销请求使用keepalive支持页面刷新时的尽力发送；服务端60秒有效期与父会话绑定仍是最终保障。
验证错误不清除有效USER会话；429按Retry-After禁用继续验证并展示等待提示。

付款前先保存恢复标记，内容仅为请求键、订单版本和retryable布尔值，sessionStorage按用户/订单分隔。
草稿转换请求键同样按用户/草稿/版本保存，网络失败后只有明确点击才用原键恢复，不自动创建订单。
存储被禁用或写入失败时不发起付款；无法读取已有恢复标记时保留查询能力并禁止再次付款。

| 结果 | 页面行为 |
| --- | --- |
| PAID | 显示原回执、清理恢复标记；刷新只GET，钱包从Java重新读取 |
| CLOSED | 显示关闭原因，不再提供验证或付款 |
| 网络失败、UNKNOWN、REGISTERED | 显示“正在核实付款结果”，只允许GET查询原订单 |
| PAYMENT_REQUEST_NOT_FOUND | 继续查询本人原订单，不能据此断言未扣款或自动重付 |
| REJECTED | 显示业务原因，等待用户修正并重新明确验证 |
| TRANSACTION_RETRYABLE/NOT_APPLIED | 保存原请求键，用户重新验证并明确点击后才能同键重试 |
| 调价/资格/版本/到期变化 | 重新GET核对权威状态，终态停止付款，引导返回草稿 |
| 缺货/余额不足/授权失效 | 展示原因，清理原授权；不自动验证或再次扣款 |

持续REGISTERED或缺少登记记录的未知结果仍需后续核实；本阶段没有通过超时猜测付款失败，也没有提供自动解锁重付按钮。

python scripts/m51c_browser_fixtures.py prepare
