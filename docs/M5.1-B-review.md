# M5.1-B 审查

审查范围：订单转换、支付授权、资金事务、重放恢复、旧成交旁路、模型摘要、演示迁移和隔离脚本。

| 审查点 | 结果及证据 |
| --- | --- |
| USER与代理权限 | 两种代理角色不能验证或付款；跨用户订单404；模型只读PAID白名单摘要 |
| 资金一致性 | 扣款后注入异常全部回滚；余额、库存、积分、流水、支付记录、订单、请求及授权保持一致 |
| 幂等与并发 | 同键重复、不同键同订单、最后库存、付款与关单均覆盖；请求指纹不随键重用改变 |
| PIN保护 | 独立事务保存失败计数；五次错误锁定；限制UTF-8字节数，拒绝非字符串 |
| 失效与恢复 | 有效期在锁后复核；授权绑定会话；确定拒绝提交撤销；未知结果使用只读恢复 |
| 旧旁路与历史数据 | 新模式禁用旧直接成交；NULL不推定PAID；支付审计存在时禁止退回旧模式 |
| 迁移与恢复 | 专用库守卫、私有备份、DDL中断续跑、零新增重跑、临时库恢复和结构指纹 |
| 正常库隔离 | 七张业务表只读哈希核对未变；临时测试账号无正常库权限 |

审查中补充修正：快照名称完整性、积分溢出保护、最终会话复核、授权实际使用时刻、严格密码类型、部署证明结构指纹和安全错误禁用缓存。
真实响应契约比对发现成功响应有重复no-store头：将安全层no-store仅放在鉴权失败响应，正常响应由Controller设置，消除重复头。
MySQL临时账号先通过受限预连接完成认证，保留JDBC禁止公钥自动获取设置；恢复库名按本机MySQL大小写规则核对。

自动审批曾因正常栈同时运行而拒绝重跑联调；随后只读确认演示端口、进程标记、固定库守卫后获准执行，未绕过审批或改用正常库。
运维测试在受限临时目录遇到Windows ACL原子替换限制，改在本机允许ACL的执行环境运行17项全部通过，未删减测试。

结论以最终[M5.1-B-validation.md](M5.1-B-validation.md)证据为准。仍待M5.1-C完成独立付款UI，M5.1-D完成浏览器断网、切号、迟到响应及可用性验收。
尚未演练真实数据库连接在COMMIT后丢失应答；UNKNOWN分支已定义，不能将事务回滚注入等同于该网络故障实测。
第三方支付、退款、对账和医疗资料审核不属于本次交付。
