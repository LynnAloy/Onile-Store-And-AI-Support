# M5.1-A 验收与审查

日期：2026-10-28。结论：设计子阶段完成，无未决阻断设计项；支付实现尚未开始。

交付：M5.1-A-design.md、m51-payment.openapi.json、sql/M5.1-A.proposed.sql、

本次核对了OrderService、OrderController、DraftService、CredentialVerifier、
SecurityConfig与M1/M4现有SQL，修正以下易误用设计：

| 审查点 | 冻结决定 |
| --- | --- |
| CONFIRMED不等于成交，confirmed草稿不自动过期 | 首次checkout另检查原草稿期限；已转换请求重放返回唯一来源订单 |
| 历史completed缺少新授权证据 | 历史支付字段保持NULL，读模型LEGACY_UNVERIFIED，不猜测回填 |
| 旧下单接口直接校验密码并成交 | B阶段启用M5时同时禁用旧直接结算入口并迁移Form页面 |
| 一次性token消费导致成功重放被误拒绝 | USER所有权和持久幂等结果/PAID优先，之后才校验活跃授权 |
| 同键失败后请求体变化、响应丢失 | 独立登记指纹、REGISTERED/SUCCEEDED/REJECTED，GET带paymentRequestKey恢复 |
| 异常抛出使授权撤回或失败次数回滚 | 密码计数独立提交；业务拒绝先提交决策状态再映射HTTP错误 |
| REQUIRES_NEW放在持有用户锁的事务内 | 验证必须在外层业务锁之外，业务事务再次验证状态和身份 |
| 会话删除导致付款审计丢失 | 付款记录不外键依赖会话/授权行；订单和流水不物理删除 |
| 两个表互相外键导致无法插入 | 支付记录引用已有流水；流水不反向引用支付记录，同一事务创建 |
| GET兼容字段和金额类型升级 | 保留旧字段名并提供适配，v5定点字符串需同步前端，不宣称零修改升级 |
| SQL被提前自动执行或DDL回滚误判 | 提案仅放docs/sql；不进入现有迁移器；增量留存、停写备份和逐条恢复 |
